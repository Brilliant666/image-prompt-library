# API 连接：先识别，再保存

在设置的「API 配置 → API Key 配置」管理连接。API Key 与账号 OAuth
仍是不同入口，账号连接的登录流程不变。

## 新建与编辑

点击「添加连接」，先选择 OpenAI、Google Gemini、Seedream、Muse 或自定义服务。
自定义服务可选择 OpenAI 兼容、Gemini GenerateContent 或 Seedream 图片协议，
包括提供原生协议的第三方中转。协议以服务文档为准，不由模型名称推断。

选择后只显示一份连接表单：名称、Base URL、API Key，然后识别模型。
已保存连接直接显示实际协议和用途；没有第二个协议下拉框，也不根据地址
自动把已有连接改成某个品牌预设。

更换已有或填写中的连接类型，需要确认将要变更的地址、Key、模型及传输
设置。取消时原输入不变。名称和网络设置保留；确认后必须检查新地址和
适用密钥。已保存密钥不会显示在页面中，也不能自动转用到另一个地址或协议。

复制、排序、默认连接、删除及本浏览器生图参数重置仍然可用。未保存更改
需要先保存或放弃，才能切换、复制或排序连接。连接默认值不会改写已冻结
任务、历史配方、现有文字或参考图。

## 保存前识别模型

填写地址和 Key 后点击「识别模型」，无需先保存连接。后端按当前草稿的
协议和网络设置读取模型清单，不生成图片、不发送聊天、不创建任务，也不
保存草稿 Key、连接文档或模型缓存。编辑已保存连接时，只有地址及协议仍
相同，才能在后端使用原密钥；页面不读取它。

模型清单显示在主流程中，可搜索和按文字、图片、待确认筛选。能力标签只
来自明确的接口输出能力或受维护的文档记录；模型名称及视觉输入能力不构成
文字或图片输出能力证明。冲突和缺失声明保持未知。

选择图片或未知模型可设为本连接的默认图片模型。仅声明文字输出、未明确
声明图片输出的模型只加入可用模型，不覆盖图片默认值；明确同时声明两类
输出的模型仍可选择为图片默认。在 Agent 设置中另行选择文字连接和模型。
识别不会自动改变当前模型、手填列表或正在编辑的提示词。

画廊与 Agent Hybrid 的生图列表按输出能力展示，不限制为 gpt-image：
声明图片输出的模型优先，其后保留能力待确认的模型和自定义 ID。
明确的纯文字或非图片模型默认不推荐；用户已选择的历史模型仍保留，
也可手填完整 ID。模型名称不构成能力证明，列表声明及文档参考也不表示
账号权限或实际调用已经验证。选择模型不会自动更改连接协议。

识别失败仍可手填完整模型 ID 并保存。重新识别时清除上次成功标记；失败后
可保留旧清单供参考，但不会将其标成当次验证成功。读取期间改变地址、Key、协议或网络
设置，旧结果不会用于新草稿。切换连接、放弃修改或关闭设置也会撤销当前
页面对旧结果的接收。模型清单读取成功不等于实际生成或计费已经验证。

**Seedream 当前使用文档参考列表，不是联网账号检测。** 按钮为「查看参考
模型」，不声称连接、Key 或账号权限通过。参考列表也不保证当前账号能使用
每个条目；Endpoint ID 与自定义别名仍可手填。

保存只写配置，不隐式再次识别。刚才识别的列表在当前表单保留；用户选定
的模型和默认值随连接保存。完整草稿识别结果不落盘，重新打开时可读取已有
的历史缓存或再次主动识别。旧的已保存模型清单刷新接口继续兼容已有调用方。

## 文字和图片的用途

OpenAI 兼容连接可用于项目的 Responses 文字调用及 Images 图片调用，具体
支持情况取决于服务与模型。可以选择同一连接的不同模型，也可以混用两份连接。

Gemini／Seedream 原生连接目前用于 Gallery 与 Agent Hybrid 的图片生成；
文字主控继续使用单独的 Responses 连接。这是本项目的适配范围，不是对厂商
所有模型能力的限制。Native Agent 和现有 OAuth 执行方式保持不变。

### Muse（muse2api）

连接类型按 OpenAI、Google Gemini、Seedream、Muse、自定义服务排列。
选择 Muse 预设后填写自己部署的 muse2api 地址及 Key，也可以使用普通自定义
连接的自动识别，无需重新创建已有连接。协议仍为 OpenAI 兼容 Images。

OpenAI 兼容连接默认使用「自动识别」：主动识别模型时，只有接口返回的清单
恰好包含 `muse-image`、`muse-spark`、`muse-video` 三个模型且各自明确标记
`owned_by: muse`，当前表单才会自动选择 Muse 适配，并显示识别结果。
不根据网址、单个模型名称、缓存或仅凭 `m2a_` Key 前缀改变请求方式。
前缀只提供本地提示；自定义 Key 同样可以通过完整模型清单识别。

识别仍只执行一次模型清单 GET，不保存连接或创建图片任务。用户点击保存后，
适配才对后续新任务生效；已有冻结任务、模型选择、Key 和其他输入保持。
识别失败或信号不足时不强行切换，也不继续展示上次识别成功。
更换地址、Key、地址规则或网络设置会使旧的自动识别失效，恢复标准兼容适配，
可重新识别新连接；只修改名称或模型不会影响适配。
高级设置保留自动识别、标准 OpenAI 兼容和手动 Muse 覆盖；手动选择优先，
不会被后续识别结果覆盖。选择 Muse 品牌预设也是一次明确的手动选择。

- `muse-image` 用于画廊、Agent Hybrid 和已确认提示词直接生成，复用现有
  图片队列、结果恢复及 Library 收录。编辑请求按重复的 `image` 字段上传
  参考图；其他 OpenAI 兼容服务继续使用 `image[]`。
- 图片设置提供自动、1:1、16:9、9:16、4:3、3:4 比例，不承诺精确像素、
  4K、质量等级、透明背景、指定文件格式或审核参数。实际图片按返回的
  原始格式保存。兼容的旧像素参数只用于推导比例，不能推导时要求重新选择。
- 最多 4 张参考图，单张不超过 10 MiB，总计不超过 24 MiB。超限在调用前
  拒绝，不自动缩图或重发。使用同步最终结果，不启用中间预览或异步任务协议。
  多张生成沿用本项目的一张一任务，不依赖服务的 `n` 批处理。
- `muse-spark` 是文字模型，但当前 muse2api Responses 没有提供本项目 Agent
  主控所需的视觉输入和结构化工具调用。Agent 文字主控请使用另一份支持这些
  能力的 Responses 连接，图片连接选择 Muse；不自动替换成其他文字协议。
- `muse-video` 是视频模型，本项目尚无对应视频任务、轮询和资产界面，不能
  通过选择该模型在图片队列中生成视频。

识别模型仍读取实际 `/models` 清单；上述三个 ID 的缺失能力声明可依据
Muse 文档标记用途，不额外补造账号模型，不把文档参考当作生成验证。
切换适配会使旧目录失效；已排队任务保留原适配身份，不静默改变请求格式。
旧配方与当前连接的适配不一致时，需明确重选连接，才会采用该连接的参数；
原 Prompt、附件和旧参数保留，不会直接转换后提交。

自动识别结果绑定地址、Key、地址规则和网络身份。更改这些设置后，重新识别
可以直接接着保存，保存本身不会再次请求供应商。识别证据仅短时保存在本地进程；
若已过期或服务已重启，保存会提示重新识别，也可明确选择手动 Muse 适配。
旧客户端仅修改连接字段、未重新选择适配时，旧自动识别结果会失效。

适配契约依据 [muse2api 源码（固定版本）](https://github.com/czg86389-hub/muse2api/blob/1cd01682533dbf2c015fa879a8dc09534b50b4a3/app.py)。
本项目保留并发送用户选择的 Prompt 原文；该版本的上游服务仍会自行整理文本、
追加比例和生图指令，参考图编辑还会追加去除文字、水印及 Logo 的要求。
因此不能将本地原文保留理解为 Muse 内部执行文本完全相同。

## 高级设置

统一的高级入口按职责分组：

- 地址规则：标准版本路径或精确根路径，以及实际端点预览。
- 网络：直连、环境或指定代理，以及超时。
- 协议传输：当前适配器支持的流式、预览或结果返回方式。
- 补充模型、模型读取时间与本浏览器的生图参数记忆。

尺寸、质量、比例、背景等本次图片参数仍放在生成界面。高级设置不会自动
降画质、上传图片到第三方图床，或在失败后切换端点重发。

## 实现与兼容

公共编辑器为 `ApiConnectionsSettings`，连接类型为 `ApiConnectionProfile`，
前端通过 `apiConnections` 访问连接操作。旧组件导出、类型名称和 HTTP 路由
保留兼容入口；供应商适配器继续使用准确的协议名称。

新增 `POST /api/generation-providers/api-connections/models/preview` 仅用于
显式的草稿识别。它保留同源保护，限制请求大小、并发、模型清单体积和耗时，
禁止跳转及自动重试，响应为 `Cache-Control: no-store`。错误不回显提交的
密钥或供应商原始消息。已有配置文件位置、任务 provider ID、冻结指纹与
结果恢复语义不变，无数据库迁移。

自动回归和隔离浏览器使用合成数据及模拟供应商；真实 Key 权限、网络出口、
具体账号模型和生成质量仍需要用户主动验收。不要把模拟通过描述为真实服务已验证。
